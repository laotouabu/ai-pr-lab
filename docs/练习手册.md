# 练习手册：从 commit 到 merge，走一遍完整 PR 流程

> 目标：跑通 **建仓库 → 分支 → 提交 → PR → CI → AI 评审 → 修改 → 合并**。
> 全程用 Windows PowerShell，命令可以直接复制。

---

```powershell

```


## 3. 配 AI 评审（两种选一种）

### 方案一：Copilot code review（最简单）

仅需 Copilot 订阅。开 PR 后在右侧 **Reviewers** 里选 `Copilot` 即可。

### 方案二：用 opencode Go 额度（本仓库自带）

1. 打开 <https://opencode.ai/console>，复制一个 API Key（`oc_sk_...`）
2. 仓库页面 → **Settings** → **Secrets and variables** → **Actions**
3. **New repository secret**
   - Name: `OPENCODE_API_KEY`
   - Secret: 粘贴你的 key
4. 回到 **Actions** 标签，如果提示 workflow 未启用，点 **I understand my workflows, go ahead and enable them**

没配 key 也没关系，`AI Review` 这个 job 会打印 `OPENCODE_API_KEY not set, skipping AI review` 然后正常结束。

> 想换模型改 `.github/workflows/ai-review.yml` 里的 `OPENCODE_MODEL`，
> 可选值见 <https://opencode.ai/v2/docs/console/go>（如 `glm-5.3-flash`、`kimi-k2.7-code`）。

## 5. 练习二：故意让 CI 变红，再修绿

这是最有价值的一步：体验「CI 拦住问题 → 修 → 自动重跑」。

```powershell
git switch main
git pull
git switch -c feat/stdev
```

在 `src/calc/stats.py` **末尾**加上这个版本（注意：**故意有 bug**，除的是 `n` 而不是 `n-1`）：

```python
def stdev(values):
    """Return the sample standard deviation."""
    data = _as_floats(values)
    if len(data) < 2:
        raise ValueError("stdev() requires at least two values")
    m = sum(data) / len(data)
    return (sum((x - m) ** 2 for x in data) / len(data)) ** 0.5
```

在 `tests/test_stats.py` 末尾加测试：

```python
def test_stdev_sample():
    # 样本标准差：statistics.stdev([1, 2, 3, 4]) == 1.290994...
    assert stdev([1, 2, 3, 4]) == pytest.approx(1.2909944487358056)


def test_stdev_needs_two_values():
    with pytest.raises(ValueError):
        stdev([1])
```

记得改 import：

```python
from calc.stats import clamp, mean, median, stdev
```

提交并开 PR：

```powershell
git add .
git commit -m "feat: add stdev helper"
git push -u origin feat/stdev
```

PR 里会发生：

1. `test (py3.9)` 等 job **变红**，日志里能看到断言失败（算出来是 1.118，期望 1.29）
2. AI 评审大概率会指出「分母应为 n-1（贝塞尔校正）」
3. 这时**不要重新开 PR**，直接在同一个分支修：

```powershell
# 把 / len(data) 改成 / (len(data) - 1)
```

```powershell
git add src/calc/stats.py
git commit -m "fix: use Bessel correction for sample stdev"
git push
```

回到 PR 页面：

- CI 会自动重跑并变绿
- AI 评论会被**更新**（不是再贴一条），因为脚本按标记做了 upsert

然后合并。

## 6. 练习三：让 AI 评审挑刺

```powershell
git switch main
git pull
git switch -c feat/percentile
```

新增（故意不处理 `q` 越界和空列表）：

```python
def percentile(values, q):
    """Return the q-th percentile (0 <= q <= 100) using linear interpolation."""
    data = sorted(_as_floats(values))
    pos = (len(data) - 1) * q / 100
    lower = int(pos)
    upper = min(lower + 1, len(data) - 1)
    return data[lower] + (data[upper] - data[lower]) * (pos - lower)
```

只写一个正常用例的测试：

```python
def test_percentile_basic():
    assert percentile([1, 2, 3, 4], 50) == pytest.approx(2.5)
```

提交、开 PR，然后看 AI 评审会不会指出：

- 空列表会 `IndexError`
- `q < 0` / `q > 100` 没有校验
- 缺少 `q=0`、`q=100` 的边界测试

按评审意见补齐，再推一版。

## 7. 开分支保护（把流程变成规则）

仓库 → **Settings** → **Rules** → **Rulesets** → **New ruleset** → **New branch ruleset**：

1. Name：`protect-main`
2. Enforcement status：**Active**
3. Target branches：**Include default branch**
4. 勾选：
   - **Require a pull request before merging**（Required approvals 设 0 或 1）
   - **Require status checks to pass**
     - 搜索并添加：`lint (ruff)`、`test (py3.9)`、`test (py3.11)`、`test (py3.12)`
   - **Block force pushes**
5. Create

之后你直接往 main push 会被拒绝，必须走 PR + CI 通过。

> 公开仓库免费能用；私有仓库的部分规则需要 GitHub Pro/Team。

## 8. 进阶玩法

| 想练什么 | 怎么做 |
| --- | --- |
| 行内评论 | 在 PR 的 **Files changed** 里点行号 `+`，写 `suggestion` 块，直接提交建议 |
| 要求人工 review | Rulesets 里把 Required approvals 设 1，再找个小号或用第二个账号 review |
| 控制 PR 大小 | 约定 < 400 行；拆成多个 PR |
| 自动标签 | 加 `actions/labeler`，按路径打 `area:src` / `area:tests` |
| 覆盖率门槛 | `pytest --cov=calc --cov-fail-under=90`，需要 `pytest-cov` |
| 安全扫描 | Settings → Code security 里开 Dependabot / CodeQL |
| 发布 | 打 tag `v0.1.0`，加一个 `release.yml` 构建 wheel |

## 9. 常见问题

**Actions 没触发？**
Settings → Actions → General → 选 **Allow all actions and reusable workflows**。

**AI review 报 403 / 不能评论？**
来自 fork 的 PR，`GITHUB_TOKEN` 是只读的，脚本会打印评审内容但贴不上评论。自己的分支没这个问题。

**`ruff check .` 报 UP 规则？**
本项目 `target-version = "py39"`，已用 `from __future__ import annotations`。如果你的新代码用了 3.10+ 语法（如 `int | None` 在运行时求值），CI 会挂。

**想改 CI 矩阵版本？**
编辑 `.github/workflows/ci.yml` 里的 `matrix.python-version`。

**合并方式怎么选？**
练习阶段用 **Squash and merge**，主干历史最干净；想保留每个 commit 就用 **Create a merge commit**。

## 10. 附：GitHub Actions 被锁时的本地模式

如果 Actions 报 `The job was not started because your account is locked due to a billing issue`，
说明是账号级计费锁，和代码无关。工单处理期间可以先用本地脚本，流程完全一样。

**1. 装上 pre-push 钩子（推送前自动跑 CI）**

```powershell
git config core.hooksPath .githooks
```

之后每次 `git push` 都会先执行：

```
ruff check .  →  pytest  →  通过才允许推送
```

**2. 手动跑一遍**

```powershell
powershell -ExecutionPolicy Bypass -File scripts\check.ps1
```

**3. 本地版 AI 评审**

```powershell
$env:OPENCODE_API_KEY = "oc_sk_..."
uv run python scripts/review_local.py
```

或者把 key 写进项目根目录的 `.env`（已被 `.gitignore` 忽略）：

```
OPENCODE_API_KEY=oc_sk_...
```

它会对 `main...HEAD` 的 diff 输出评审意见，等价于 `AI Review` 那个 workflow。
换模型：

```powershell
uv run python scripts/review_local.py --model glm-5.3-flash
```

**4. 账号解锁后切回去**

```powershell
git config --unset core.hooksPath
```

然后去 Actions 里 **Re-run all jobs**。
